# 요청이 들어오면 — 처리 절차

선생님 한 분의 요청이 사이트 게시판에 올라가기까지 지나는 길이다.
12월에 이 일을 물려받는 사람이 처음 읽는 문서로 쓴다. 개발 용어는 쓰지 않는다.

## 1. 선생님이 하는 것

선생님은 「요청하기」 폼(노션)에 적는다. 지금은 칸이 하나다 — 「요청 내용」.
유형이나 담당 교과를 고르는 칸은 아직 없다. 필요하면 코디네이터가 나중에 물어본다.

폼 링크가 사이트에 아직 없다(7절 참고). 그래서 지금은 **수·목 오전 교무실, 종이 쪽지,
업무 메신저**로도 받는다. 사이트 `request/` 쪽의 「새 요청 쓰기」는 아직 보낼 문장을
만들어 드리는 데까지만 한다 — 눌러도 어디로 가지는 않는다.

이렇게 적어 주시면 빠르다.
1. 어떤 일인지 한 줄 — 예: "체육대회 안내 팜플렛을 매년 외주로 맡깁니다"
2. 언제까지 필요한지 — 날짜만 적어도 된다
3. 지금은 얼마나 걸리는지 — "한 번에 서너 시간" 정도면 충분하다

## 2. 어디로 들어오는가 — Notion 두 곳

노션에 이름이 비슷한 DB가 두 개 있다. 역할이 다르다. 헷갈리면 안 된다.

| | 「📨 요청 접수」 | 「노안중 AI교육 — 요청 게시판」 |
|---|---|---|
| ID | `da73389c71664dc5a2fba8a01f67117e` | `39eb7d4e6d46446db925fbd099f9ade7` |
| 공개 범위 | 코디네이터 **비공개** 작업대 | 사이트에 **공개**되는 것만 |
| 들어오는 길 | 선생님용 폼 뷰 「요청하기 (선생님용 폼)」 | 없음 — 코디네이터가 손으로 옮겨 적는다 |
| 코디네이터가 보는 뷰 | 「상태별 보드」 | (해당 없음) |
| 주요 속성 | 요청 내용(제목) · 유형 · 담당 교과 · 요청자(선택) · 상태 · 접수일(자동) · 완료일 · 처리 메모 · 소요 시간(분) · 산출물 · 보고서 반영 | 제목 · 내용 · 유형 · 상태 · 소속 · 답변 · 공감 · 공개(체크) |

「📨 요청 접수」는 일을 처리하는 작업대다. 선생님 이름, 처리 과정, 걸린 시간이 그대로 있다.
「요청 게시판」은 사이트에 보일 것만 옮겨 적는 곳이다. 이름은 원래부터 안 넣는다.

## 3. 코디네이터가 하는 것 (수·목 오전)

코디네이터는 수·목 오전에 학교에 있다. 요청은 이 시간에 확인하고 처리한다.
운영 페이지에 적힌 말로 하면: "선생님은 「요청하기」 폼으로, 나는 「상태별 보드」로.
처리하면 활동 기록에도 한 줄."

### 3-1 접수 확인

「📨 요청 접수」의 「상태별 보드」 뷰를 연다. 폼으로 막 들어온 것, 종이 쪽지로 받아서
직접 입력한 것이 「접수」 칸에 있다. 유형과 담당 교과가 비어 있으면 채운다.
요청자는 선택이다 — 이름 대신 교과만 써도 된다.

### 3-2 처리

카드를 「진행」으로 옮기고 실제로 손을 댄다. 어떤 도구로 어떻게 했는지는
처리 메모에 적어 둔다. 나중에 같은 요청이 또 오면 이 메모를 그대로 다시 쓴다.

### 3-3 상태 바꾸는 기준

- **접수** — 폼으로 들어온 직후. 아직 손대지 않았다.
- **진행** — 손을 댄 날.
- **완료** — 산출물을 선생님께 전달하고 「받으셨죠?」 확인한 날. 이때 **완료일 · 소요
  시간 · 처리 메모를 반드시 채운다.** 소요 시간은 결과보고서의 절감 시간 근거가 된다 —
  나중에 몰아서 채우려 하면 기억이 안 난다.
- **보류** — 학교 확인이 필요하거나 개인정보 문제로 멈춘 것. 보류 사유를 처리 메모에 적는다.

### 3-4 활동 기록

처리한 건은 「📅 활동 기록」에도 한 줄 남긴다. 이 기록이 결과보고서의 원천이 된다.

### 3-5 게시판에 공개할지 정하기

처리가 끝난 요청 중 **다른 선생님에게도 도움이 될 만한 것만** 「요청 게시판」에 옮겨
적는다. 요청자·학생이 드러나는 표현은 지운다. 소속은 비우면 익명으로 나간다.
옮겨 적은 뒤 「공개」를 켠다 — 켠 것만 사이트에 나간다.
「📨 요청 접수」 쪽 「보고서 반영」 칸도 미분류 → 반영대상/반영완료/제외 중 하나로 정리한다.

## 4. 사이트에 내보내기 — 명령 세 줄

「공개」를 켠 뒤, 요청을 처리한 날에 아래 세 줄을 돌린다.

```
NOTION_TOKEN=... NOTION_REQUESTS_DB=39eb7d4e6d46446db925fbd099f9ade7 node tools/sync-requests.js
node tools/sync-data.js
git add data/requests.json data/requests.js && git commit -m "data: 요청 게시판 내려받기" && git push
```

**토큰은 파일에 적지 않는다.** 명령을 실행하는 그 자리에서만 넣는다. 저장소에도,
메모장에도 남기지 않는다.

## 5. 개인정보 — 절대 규칙

`tools/sync-requests.js`는 안전장치를 코드로 두고 있다.

- `NOTION_TOKEN`, `NOTION_REQUESTS_DB` 환경변수가 없으면 아예 실행되지 않는다.
- 「공개」가 켜진 줄만 가져온다. 선생님이 보낸 원문이 곧바로 사이트에 올라가지 않는다.
- 제목·내용·답변에 "OO 선생님/샘/님/학생" 같은 이름 패턴이 보이면 **전체 실행을 멈춘다.**
  완벽하게 걸러내는 게 목적이 아니라, 한 번 멈춰 세워 사람이 보게 하는 게 목적이다.
  걸리면 노션에서 그 자리를 지우거나 "담당 선생님" 처럼 바꾼 뒤 다시 돌린다.

이 세 가지는 사람의 주의력이 아니라 코드에 맡겨 둔 것이다. 바꾸지 않는다.

`https://docs.google.com/forms/d/e/1FAIpQLSdXFr-pmO6_a7lw-KvGB3l2XY-BPvpJNJfKeJLTNE_Q7L7yBQ/viewform`

노션에도 「📋 교원 설문」 DB가 있지만, 덱의 QR이 실제로 가리키는 곳은 구글 폼이다.
구글 폼으로 받는다. 집계는 코디네이터가 한다. Notion 설문 DB와의 관계는 확인이
필요하다 — 아직 정리되지 않았다.

(17번 슬라이드 QR은 이것과 다르다. 그건 사이트 홈 `https://zln02.github.io/noan-ai/` 로 간다.)

## 7. 아직 비어 있는 것

- 폼 공개 링크가 사이트(`request/index.html`의 `data-form`)에 아직 없다.
- 설문 응답이 어디에 모이고 누가 집계하는지 — 6절 참고.
- 요청하기 폼의 질문이 「요청 내용」 한 칸뿐이다. 유형·교과를 물어보는 칸을 더할지는
  정해지지 않았다.
- `assets/qr-request.svg`가 만들어져 있지만 어느 페이지에도 붙어 있지 않다.

## 8. 12월 이후 — 물려받는 사람에게

이 절차를 이어받으면 아래를 먼저 바꿔야 한다.

- **Notion 워크스페이스 접근 권한** — 「📨 요청 접수」, 「요청 게시판」, 「📅 활동 기록」
  세 곳 모두 새 담당자 계정으로 넘겨받는다.
- **NOTION_TOKEN 재발급** — 떠나는 사람의 토큰은 폐기한다. 그 토큰으로 계속 돌리지 않는다.
- **수·목 시간을 자기 근무시간으로** — 3절의 주기는 전임자의 근무 요일이었다. 자기
  근무표에 맞는 요일로 바꾸고, 이 문서의 "수·목 오전"도 그에 맞게 고친다.
