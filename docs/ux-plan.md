# 선생님용 UX 재정렬 계획

새 사이트를 만드는 문서가 아니다. **기존 구조·URL·데이터 흐름을 그대로 두고
선생님이 들어오는 길만 다시 세우는** 계획이다. 구현은 이 문서를 근거로 한다.

전제: GitHub Pages · 순수 HTML/CSS/JS · 빌드 없음 · CDN 없음 · `file://` 동작 ·
JSON+JS 이중 구조 · 로그인 없음. 이 일곱은 협상 대상이 아니다.

## 0. 먼저 — 방향과 지금 저장소가 부딪히는 곳 세 군데

이 셋은 내가 임의로 정할 수 없다. 결정을 주셔야 그다음이 진행된다.

### (가) 색 — 「블루 + 화이트」 대 지금의 학교 교색(녹색)

지금 전 화면이 `--ink #0E3B33` · `--mint #3FAE93` 녹색이다. 이유가 문서로 남아 있다:

- `tools/CONTRACT.md` — 토큰 값 변경 금지
- `docs/decisions.md` 6번 — 인쇄본 표지에 **"이 안내서의 색은 우리 학교 교색에서 가져왔습니다"** 가
  박혀 있어서, 화면만 파랑으로 가면 종이와 화면이 다른 학교 것이 된다
- 인쇄본 19쪽(A4 가로)이 이미 나와 있고 연수에서 배포된다

**선택지**
1. 녹색 유지 — 종이·덱·웹이 한 벌로 남는다. 추가 비용 0
2. 파랑으로 전면 교체 — `tokens.css` 토큰 3개 교체 + 인쇄본 재생성 + 표지 문장 수정.
   덱 24장과 안내서 16장 캡처를 다시 찍어야 한다
3. **중간안(권장)** — 바탕과 여백을 흰색으로 크게 늘려 「블루+화이트」의 **밝고 넓은 인상**을
   만들고, 강조색만 교색으로 둔다. 색은 그대로, 체감은 바뀐다

지금 화면이 답답한 원인은 색보다 **여백과 카드 개수**다. 3번이면 색을 안 건드리고도
원하시는 인상에 닿는다고 본다.

### (나) 로고 — 「실제 로고, AI 생성 금지」

- `assets/logo.png` 는 **아직 저장소에 없다.** 지금 자리만 있고 「노안중학교」 글자가 대신 선다
- 마스코트 노아리 7종(`assets/noari/`)과 파비콘은 **AI로 생성된 그림이다**
- JNE GPT 로고는 공식 배포본이 없어 지금 텍스트 뱃지로 그린다
- NotebookLM · 미리캔버스는 `shared/icons.js` 에 simple-icons(CC0) path 가 들어 있다

**필요한 것**: 학교 공식 로고 파일(png/svg). 주시면 `assets/logo.png` 에 넣고 전 화면
우상단·헤더·파비콘이 한 번에 산다. 노아리를 계속 쓸지도 정해 주셔야 한다
("AI 생성 로고 금지"가 마스코트에도 적용되는지).

### (다) 핵심 도구 세 개와 덱 대본의 어긋남

「JNE GPT · NotebookLM · 미리캔버스」 셋을 전면에 세우자고 하셨다. 그런데 덱 대본은 이렇다:

| 덱 장면 | 지금 대본의 도구 |
|---|---|
| s15 긴 공문을 읽어야 할 때 | **Gemini** |
| s16 회의·상담을 기록할 때 | **클로바노트** |

안내서 카드 02(긴 공문)는 **NotebookLM** 이라 이미 덱과 갈려 있다(`docs/decisions.md` 4번, 미결).
대본은 한 글자도 못 바꾸는 규칙이라 **승인 없이는 못 맞춘다.**

**필요한 결정**: 덱 s15·s16 의 도구 배지를 NotebookLM 쪽으로 맞출지. 맞추기로 하면
`copy-s1-b.txt` 두 줄 + `s1.html` 배지 두 곳이면 끝난다.

## 1. 유지할 것

URL 과 데이터는 그대로 간다. 바꾸는 건 **그 안의 배치**다.

| 유지 | 이유 |
|---|---|
| `/guide/` — 안내서 16장, 해시 라우팅 `#01`, 프롬프트 복사, 인쇄 PDF 링크 | QR 이 여기를 가리킨다. 주소가 바뀌면 인쇄된 QR 이 죽는다 |
| `data/*.json` + `.js` 짝 구조 | `file://` 폴백의 근거. 절대 깨지 않는다 |
| `data/tasks.json` 16장의 문장 | 인쇄본과 대조 검증한다. 한 글자도 안 바꾼다 |
| `/training/` · `/library/` · `/request/` · `/about/` 주소 | 이미 배포·인쇄물에 나갔다 |
| `/ops/` 네 쪽 + `noindex` + 내비 미노출 | 관객 분리 원칙 |
| `tools/sync-data.js` · `sync-notion.js` · `check-copy.js` | 데이터·개인정보·대본 무결성의 근거 |
| 안내서 상세의 **검은 프롬프트 박스** | 이 페이지에서 제일 많이 눌리는 것 |

## 2. 숨기거나 뒤로 보낼 것

선생님 첫 화면에서 **덜어낸다.** 지우는 게 아니라 한 단계 뒤로 민다.

| 지금 홈에 있는 것 | 어디로 |
|---|---|
| 「이번 주」 연수 카드 | `/training/` 로. 홈에는 D-day 한 줄만 |
| 「대회」 블록 | `/contest/` 로. 홈에서 뺀다 |
| 「둘러보기」 4카드(연수·수업·자료실·소개) | 푸터 링크로 강등 |
| 「이미 갖고 계신 것」 도구 뱃지 5개 | `/library/` 로. 홈에서 뺀다 |
| 「2학기 로드맵」 4칸 | `/about/` 로 |
| 아이모두 도구 12개 전체 노출 | 검색 결과와 `/library/` 도구 지도에서만 |
| 승인 현황 · 안전 규칙 | `/library/` 안에 유지(지금도 그렇다) |

**결과**: 홈에 남는 것은 **질문 하나, 검색창 하나, 업무 카드 여덟, 요청 한 줄.**

## 3. 새 사용자 여정

```
QR 찍음
   ↓
"무엇을 하시려고요?"  ← 첫 화면에서 바로 이것만 보인다
   ↓
[가정통신문] 을 누르거나 검색창에 "통신문" 입력
   ↓
업무 가이드 한 장 — 이런 때 씁니다 / 도구 / 3단계 / 프롬프트 / 확인할 것
   ↓
[복사] 눌러 붙여넣고 일한다
   ↓
안 되면 → "이 일이 오래 걸려요 → 요청하기"
```

**막다른 길을 만들지 않는다.** 어느 화면에서든 (1) 업무 찾기로 돌아가기 (2) 요청하기,
두 출구가 항상 보인다.

## 4. 홈 IA

`index.html` 을 이렇게 줄인다. 순서가 곧 우선순위다.

```
1. 헤더        로고 + 「노안중 AI교육」 + 내비 4개(안내서 · 연수 · 자료실 · 요청하기)
2. 질문        "무엇을 하시려고요?"            ← 48px 안팎, 화면에서 제일 큰 글자
3. 검색창      큰 입력창 하나
               placeholder: 가정통신문, 회의록, 긴 공문, 활동지, 설문, 발표자료
4. 빠른 업무   버튼 8개 (아래 5절 표)
5. 세 갈래     쓰고 고치기 · 읽고 찾기 · 만들고 보여주기 — 각 한 줄 + 도구 로고 1개
6. 마무리      "이 일이 오래 걸려요 → 요청하기"  ·  다음 연수 D-day 한 줄
7. 푸터        연수 · 수업 · 대회 · 자료실 · 소개 · 안전 규칙
```

내비를 6개에서 **4개로** 줄인다(수업·대회는 푸터로). 선생님이 고를 것이 적을수록 좋다.

## 5. QR 진입 IA

**`/start/` 를 새로 만들지 않는다.** 이유:

- 인쇄된 QR(`assets/qr-guide.svg`)이 이미 `/guide/` 를 가리킨다. 주소를 바꾸면 죽은 링크가 된다
- 홈(`/`)과 `/start/` 가 거의 같은 화면이 되어 두 벌을 관리하게 된다

대신 **`/guide/` 첫 화면을 QR 도착지답게** 만든다. 지금도 「무엇을 하시려고요?」로 열리지만
카드 16장이 한꺼번에 쏟아진다. 이렇게 바꾼다:

```
/guide/  첫 화면
  ├ "무엇을 하시려고요?"
  ├ 큰 검색창
  ├ 빠른 업무 8개          ← 새로 추가. 16장으로 가는 지름길
  ├ [ 16가지 전체 보기 ]    ← 접어둔다. 누르면 지금의 카드 그리드
  └ 종이 안내서 / 요청하기
```

`/` 와 `/guide/` 의 관계: **홈은 학교 사이트의 얼굴, `/guide/` 는 업무 찾기 도구.**
둘 다 「무엇을 하시려고요?」로 시작하지만 홈은 아래에 연수·소개 맥락이 붙고,
`/guide/` 는 오직 업무만 있다. QR 로 온 선생님은 후자에 도착한다.

**빠른 업무 8개 → 안내서 카드 매핑** (전부 이미 있는 카드다. 새로 만들 것 없음)

| 빠른 업무 | 카드 | 도구 |
|---|---|---|
| 가정통신문 | 01 가정통신문 쓰기 | 미리캔버스 |
| 회의록 | 04 회의록 정리하기 | 클로바노트 |
| 긴 공문 | 02 긴 공문에서 할 일만 뽑기 | NotebookLM |
| 활동지 · 문항 | 11 활동지·형성평가 문항 만들기 | JNE GPT |
| 설문 | 07 설문 돌리고 모으기 | 유레카 |
| 발표자료 | 06 발표자료 만들기 | 미리캔버스 AI |
| 자료 여러 개 비교 | 02 · 03 (공문 → 계획서) | NotebookLM |
| 문서 검토 | 01b 다 쓴 문서 검토받기 | JNE GPT |

「자료 여러 개 비교」는 **딱 맞는 카드가 없다.** 지금은 가장 가까운 카드로 보내고,
카드를 새로 만들지는 않는다. 필요하면 별도 승인 후 추가한다.

> **2026-09-09 승인 — 01b review 추가.** 1회차 시연 1번이 이 흐름이고,
> quicktasks 「문서 검토」 태그에 대응 카드가 없었다. 17장.

## 6. 업무 가이드 상세 IA

지금 상세 화면은 [단계 → 프롬프트 → 주의 → 절감시간] 순이다. 요청하신 7단 구조로 바꾼다.
**모든 항목이 `data/tasks.json` 에 이미 있다. 새 문장을 만들지 않는다.**

| 순서 | 화면 | 데이터 |
|---|---|---|
| 1 | 이런 때 씁니다 | `when` |
| 2 | 추천 도구 | `tool` + `path`(길찾기) |
| 3 | 3단계 사용법 | `steps[3]` |
| 4 | 복사할 프롬프트 | `prompt` + 복사 버튼 (없으면 `prompt_note` 민트 박스) |
| 5 | 시연 영상 / 캡처 | `shot` → `assets/guide/` + `marks` |
| 6 | 꼭 확인할 것 | `caution` |
| 7 | 공식 매뉴얼 / 추가 자료 | `data/guides.json` 에서 `tool` 이 같은 항목 |

**7번이 새로 붙는 연결이다.** 지금 `guides.json` 15건은 `/library/` 에만 있다.
같은 도구의 공식 안내를 **가이드 맨 아래 한 줄**로 끌어온다. 도구 조작은 공식 문서로,
업무 적용은 우리 카드로 — 역할이 나뉜다(`decisions.md` 8번).

## 7. 모바일 UX (390px 기준)

첫 화면(스크롤 0)에 들어가야 하는 것, 이 순서 그대로:

```
헤더 56px
"무엇을 하시려고요?"      32px
큰 검색창                 높이 52px, 탭 영역 충분히
빠른 업무 2열 × 2줄       나머지는 스크롤
```

- **업무까지 1~2탭.** 검색창 입력 또는 카드 한 번
- **프롬프트 복사 버튼은 화면 폭 가득.** 지금은 작은 알약이라 손가락으로 어렵다
- **긴 안내는 접는다.** 상세의 6번(확인할 것)과 7번(공식 매뉴얼)은 기본 접힘,
  제목만 보이고 누르면 펼친다. `<details>` 로 — JS 없이 된다
- **요청하기는 항상 도달 가능.** 상세 맨 아래 고정 링크
- 검색 입력 중 **한글 조합이 끊기지 않아야 한다**(결과 칸만 다시 그리는 방식은 이미 적용됨)

## 8. `/ops/` 와의 경계

바뀌는 것 없다. **지금 규칙을 그대로 지킨다.**

- 선생님 화면 어디에도 `/ops/` 링크를 두지 않는다
- `/ops/` 네 쪽 전부 `noindex`
- 운영 로그 · 근무 시간 · 인수인계 · 회차 기록 · 승인 현황 내부 메모는 `/ops/` 에만
- 단, **`/library/approval.html`(도구 승인 현황)은 선생님용으로 유지**한다.
  "이 도구 써도 되나"는 선생님이 물으시는 것이라 운영 데이터가 아니다
